CORRECTIF 1 — MENU ITEMS INVISIBLES DANS LA CLIENTAPP FLUTTER
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Symptôme :
  Les items créés par la nouvelle app Velox Restaurant (ex: "beef casser")
  n'apparaissaient pas dans la ClientApp Flutter, alors que les anciens
  items créés par l'app Flutter eux s'affichaient normalement.

Diagnostic via MCP Firebase :
  Comparaison des documents Firestore dans menu_items :
  - Anciens items Flutter → champ "createdAt" présent
  - Nouvel item "beef casser" (ID: Jlm3e1AYtpH5J1aNtBzT) → "createdAt" absent,
    seulement "updatedAt" présent

Cause racine :
  Dans MenuRepositoryImpl.kt, updateMenuItem() utilisait .set() au lieu de .update().
  .set() REMPLACE tout le document → efface "createdAt".
  Flow fautif dans saveItem() du MenuViewModel :
    1. addMenuItem()   → écrit "createdAt" ✓
    2. uploadMenuImage() → upload image
    3. updateMenuItem()  → .set() écrase tout le doc → "createdAt" supprimé ✗
  La ClientApp Flutter trie les items avec orderBy("createdAt"), donc
  les documents sans ce champ sont exclus des résultats Firestore.

Fichier corrigé :
  app/src/main/java/com/example/velox_restaurant/data/remote/MenuRepositoryImpl.kt
  Ligne 56 : .set() → .update()

Réparation Firestore :
  Document Jlm3e1AYtpH5J1aNtBzT ("beef casser") mis à jour via MCP Firebase :
  createdAt: "2026-04-28T21:58:49.347Z" ajouté directement en base.
  L'item est désormais visible dans la ClientApp sans rebuild.

CORRECTIF 2 — NOTIFICATIONS FCM NON REÇUES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Symptôme :
  L'app Velox Restaurant recevait les commandes en temps réel (Firestore OK)
  mais ne recevait aucune notification FCM pour les nouvelles commandes.

Diagnostic via MCP Firebase :
  Document restaurants/nudaILRLqLRDfriLe3xmDehrvvJ2 (Burger King) :
  - fcmToken: null   ← token absent !
  - fcmTokenUpdatedAt: "2026-04-26T07:46:29.521Z"  ← timestamp présent mais token null
  La Cloud Function essayait d'envoyer à null → échec silencieux.

Cause racine :
  RestaurantFcmService.onNewToken() sauvegarde le token seulement quand il change.
  Si l'appareil avait déjà un token FCM (installé avant ou token non expiré),
  onNewToken() ne se déclenche pas → token jamais sauvé en Firestore.
  Au login, le token actuel n'était jamais récupéré ni persisté.

Fichier corrigé :
  app/src/main/java/com/example/velox_restaurant/data/remote/AuthRepositoryImpl.kt
  Ajout après la vérification isActive :
    val token = FirebaseMessaging.getInstance().token.await()
    → sauvegarde fcmToken + fcmTokenUpdatedAt dans restaurants/{uid}
  Désormais, à chaque login le token FCM actuel est fetch et sauvé.

Imports ajoutés :
  - com.google.firebase.messaging.FirebaseMessaging
  - com.google.firebase.firestore.FieldValue

Action requise :
  Se déconnecter et se reconnecter dans l'app pour déclencher le fetch
  du token FCM et le sauvegarder en Firestore.
